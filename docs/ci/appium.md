# Appium на устройстве фермы

[Все интеграции и их статус](README.md) · [API и CLI](../api/README.md)

Ферма выделяет Android-устройство, а Appium работает на машине, где запущены тесты. CLI подключает устройство по ADB и передаёт его адрес в `ANDROID_SERIAL`. Существующие тесты Appium можно оставить: задайте им этот адрес в capability `appium:udid`.

## Размеры памяти устройства и параметры запуска

Все настройки передаются через общий CLI: `RDF_DISK_GB` — внутренняя память Android, `RDF_SD_CARD_MB` — SD-карта, `RDF_EMULATOR_PARAMS` — дополнительные разрешённые аргументы. Они задаются до `rdf.sh run`; [значения и ограничения](../api/README.md#память-устройства-sd-карта-и-аргументы-запуска) совпадают с веб-интерфейсом.

## Что установить на машине с тестами

- Node.js 24 и npm 10 или новее.
- Git для установки закреплённого исходного релиза UiAutomator2.
- JDK 17 или 21; `JAVA_HOME` указывает на каталог JDK.
- Android SDK с Platform Tools и Build Tools; `ANDROID_HOME` указывает на каталог SDK, `adb` доступен в `PATH`.
- Bash, `curl`, `jq` и GNU `timeout` для CLI фермы.
- Доступ к HTTPS фермы и её ADB-портам.

Управление устройством использует обычный ADB. Ферма запускает выбранный профиль устройства; локальные инструменты SDK нужны клиенту Appium для подключения и установки тестовых компонентов.

В примере закреплены Appium 3.8.0 и UiAutomator2 8.7.0. Небольшой [клиент W3C/Appium](../../examples/appium/client.mjs) использует встроенный `fetch` Node.js 24 и реализует только команды этого smoke-теста. Своё приложение продолжайте проверять привычным Appium-клиентом. Зависимости устанавливаются внутри примера:

```bash
npm ci --prefix examples/appium
```

На Windows upstream-скрипт сборки драйвера использует POSIX shell. Выполните установку с Git Bash (путь зависит от места установки Git):

```powershell
$env:npm_config_script_shell = 'C:\Program Files\Git\bin\bash.exe'
npm ci --prefix examples/appium
```

Глобальная установка Appium и отдельный `appium driver install` не нужны: сервер находит UiAutomator2 в зависимостях проекта. [Как Appium загружает локальные драйверы](https://appium.io/docs/en/latest/guides/managing-exts/#do-it-yourself-with-npm).

## Запустить готовую проверку

Пример рассчитан на Android 11 для телефона или планшета с английским или русским интерфейсом. Он открывает системные настройки, находит «Сеть и Интернет» и сохраняет скриншот. Свой APK не требуется. UiAutomator2 установит на устройство служебные компоненты тестирования.

Из корня репозитория фермы:

```bash
export RDF_URL='https://farm.example.com'
export RDF_PROFILE='android-30'
export RDF_ADB_KEY_ID='33333333-3333-4333-8333-333333333333'
read -rsp 'API-токен: ' RDF_TOKEN
printf '\n'
export RDF_TOKEN

bash scripts/rdf.sh run -- node examples/appium/run.mjs
```

Замените адрес, профиль и ID ключа своими значениями. Соответствующий закрытый ADB-ключ должен быть доступен локальному ADB-серверу; публичная часть — добавлена в ваш аккаунт фермы. CLI не меняет ключ по умолчанию и не перезапускает общий ADB-сервер.

Команда сама запускает Appium на `127.0.0.1:4723`, выполняет проверку, закрывает Appium и освобождает устройство. Если порт уже занят, она завершится с понятной ошибкой. Для другого порта задайте `APPIUM_PORT`, например `4725`.

[Исходник проверки](../../examples/appium/settings.test.mjs) · [Запуск Appium и сбор отчёта](../../examples/appium/run.mjs).

## Где результаты

По умолчанию файлы появляются в `examples/appium/artifacts/`:

| Файл | Содержимое |
| --- | --- |
| `appium.xml` | Отчёт JUnit, если запуск теста начался |
| `appium.log` | Журнал локального сервера Appium, включая ошибки подключения |
| `settings-home.png` | Скриншот успешной проверки |
| `failure.png` | Попытка снять экран при ошибке проверки, если устройство ещё доступно |

Для другого каталога задайте абсолютный путь в `RDF_ARTIFACTS_DIR`. Перед новым запуском пример удаляет только четыре своих файла из таблицы, чтобы старый JUnit или скриншот не выглядел результатом новой проверки. Для одновременных запусков обязательно задавайте разные каталоги. Файл `.appium.lock` с PID процесса защищает каталог от одновременной записи: второй запуск завершится, не затрагивая чужие результаты. После принудительной остановки удаляйте этот файл только после проверки, что прежний процесс завершён. Сохраняйте артефакты CI и при ошибке задания. Если освобождение не подтвердилось, CLI оставит файл восстановления и напечатает его путь: [как повторить освобождение](../api/README.md#если-запрос-или-освобождение-прервались).

## Подключить свои тесты

В настройках своего клиента используйте:

```js
const capabilities = {
  platformName: 'Android',
  'appium:automationName': 'UiAutomator2',
  'appium:udid': process.env.ANDROID_SERIAL,
  'appium:suppressKillServer': true,
  'appium:noReset': true,
};
```

Запускайте тестовую команду внутри `rdf.sh run`, чтобы продление аренды работало всё время теста. Appium-сессию закрывайте в `finally` или обработчике завершения вашего тестового фреймворка. Освобождение сессии фермы выполняет CLI.

CLI и Appium должны использовать один локальный ADB-сервер: по умолчанию это порт 5037. Пример также передаёт заданный `ANDROID_ADB_SERVER_PORT` в capability `appium:adbPort`. В своих тестах настройте тот же порт; другой ADB-сервер не увидит подключённое CLI устройство.

`remoteAdbHost` здесь не нужен: он задаёт адрес ADB-сервера. CLI уже подключил устройство к локальному ADB; его выбирает `udid`. Не включайте `--relaxed-security` и не открывайте Appium на внешнем интерфейсе для этого сценария. [Параметры UiAutomator2](https://github.com/appium/appium-uiautomator2-driver#capabilities) · [Безопасность Appium](https://appium.io/docs/en/latest/guides/security/).

Для параллельных заданий используйте отдельные runner-окружения, устройства, файлы состояния и каталоги артефактов. Пример запускает один тест на одном устройстве. Maestro и Appium не должны одновременно управлять одной сессией.

## Если проверка не стартует

- **Appium не видит устройство:** `adb devices` должен показывать ровно тот адрес, который находится в `ANDROID_SERIAL`, со статусом `device`.
- **`unauthorized`:** проверьте соответствие публичного ключа в ферме закрытому ключу локального ADB-сервера.
- **Порт занят:** закройте свой прежний Appium или задайте другой `APPIUM_PORT`.
- **`Appium artifacts are locked`:** задайте отдельный `RDF_ARTIFACTS_DIR`. Если блокировка осталась после аварии, проверьте PID из `.appium.lock` перед удалением файла; действующий запуск не прерывайте.
- **Не находится Java или Android SDK:** проверьте `JAVA_HOME`, `ANDROID_HOME`, затем из каталога `examples/appium` выполните `npx appium driver doctor uiautomator2` с незаданным `APPIUM_HOME`.
- **Не найден пункт настроек:** этот smoke-тест рассчитан на Android 11 с английским или русским интерфейсом; для другого устройства адаптируйте селектор в `settings.test.mjs`.

## Что проверено

Локально проверены установка закреплённых зависимостей, диагностика UiAutomator2 без обязательных замечаний, запуск Appium на loopback и ответ `/status`. Автотесты проверяют ответы протокола, отмену, ошибку запуска и завершение дочерних процессов. Реальный прогон этого примера на устройстве пока не выполнен. Живой сценарий Maestro описан [отдельно](maestro.md#проверенный-сценарий).

## Закрепление зависимостей и аудит

UiAutomator2 сохраняет версию **8.7.0**, но устанавливается из [официального commit релиза](https://github.com/appium/appium-uiautomator2-driver/tree/7a54db007aa8a44f5df21cd0b52afc13c0d277ae). Опубликованный npm-архив этой версии содержит старые вложенные зависимости, которые npm не заменяет через `overrides`. Исходный релиз собирается штатным `prepare`; конечное дерево фиксирует `package-lock.json`.

В `package.json` закреплены исправленные совместимые версии `axios` 1.20.0, `morgan` 1.12.1, `proxy-addr` 2.0.8, `shell-quote` 1.12.0 и `sharp` 0.35.5. Переход на Git-источник не меняет API Appium или драйвера. Возвращать npm-архив следует после исправления его вложенных зависимостей и повторной проверки установки, загрузки драйвера и аудита.

CI проверяет установку и загрузку Appium/UiAutomator2 и блокирует высокие и критические уязвимости. Локальная проверка:

```bash
npm ci --prefix examples/appium
npm audit --prefix examples/appium --audit-level=high
```

Живой smoke-тест на устройстве остаётся обязательным перед релизом: установка UiAutomator2, действия в настройках, скриншот, удаление сессии и освобождение устройства. Не используйте `npm audit fix --force` без проверки совместимости. [Общий статус интеграций](README.md).
