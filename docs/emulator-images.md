# Образы эмуляторов Android

Основной способ добавления версий Android — **Профили устройств → Каталог образов**. Выберите сборщик и registry, отметьте варианты и запустите сборку. Создание профилей, проверка загрузки/ADB и публикация по digest выполняются в фоне. Кнопки отмены доступны для очереди и активной сборки.

- [Настройка сборщика, registry и прогрева](deployment/registry.md).
- [Профили и JSON-примеры](guides/images.md).
- [Настройка узла и ресурсов](guides/administration.md).

> **Готовые сторонние образы могут отключать проверку ADB-ключей.** Перед включением профиля подтвердите, что ADB самого эмулятора отклоняет недоверенный ключ. Не публикуйте напрямую порты ADB, gRPC и консоли. [Требования и порядок проверки](guides/images.md#готовые-сторонние-образы).

## Контракт запуска

Образы запускаются стандартно; изменения ресурсов и дополнительные аргументы задаются явно. Нет скрытых оптимизаций по имени образа или версии Android. GPU выбирается при старте сессии по возможностям узла, а не отдельным образом в профиле. ATD-варианты явно помечены как образы для автотестов.

Стартовые профили без подтверждённой проверки образа выключены. [Пример манифеста](examples/profiles-test-images.json) содержит условные адрес и digest: замените их результатом успешной проверки своего образа. Собственные совместимые Docker-образы можно импортировать по тегу или digest; для воспроизводимости используйте digest. Разрешённый registry задаётся администратором узла. Сессионные ADB-ключи передаются при запуске, они не должны встраиваться в публичный образ.

Первое скачивание занимает время и несколько гигабайт. Кнопка прогрева в каталоге заранее скачивает включённые профили на узлы. Хранилище registry включайте в резервное копирование.
