# Диагностика запуска и остановки

Администратор открывает **Журнал → Аренды → нужная сессия → Лог сессии**.
В разделе **Логи сервиса** можно указать полный ID или первые восемь символов.
Текстовый лог обновляется каждые пять секунд; закрытие окна не останавливает запись.

Записи хранятся в PostgreSQL `service_logs` независимо от существования сессии:
резервирование, параметры запуска (без ключей и переменных окружения), проверка
ресурсов/KVM/GPU, подготовка образа, создание контейнера, ответы ADB,
`sys.boot_completed=1`, ошибки, остановка, удаление контейнера/томов/сетей и освобождение слота.
Отключение и восстановление агента тоже записываются.

Во время загрузки агент снимает stdout/stderr контейнера раз в 30 секунд,
а перед удалением — ещё раз. Каждый снимок содержит последние 2000 строк
с исходными временными метками; повторные строки загрузки исключаются.
На один запрос запуска сохраняется до 4000 строк вывода. Этапы и ошибки
записываются отдельно. Сохраняются состояние контейнера, exit code и OOMKilled.
Если Docker не отдаёт диагностику, это отмечается отдельным предупреждением.
Пароли, токены, ключи и произвольные значения окружения удаляются из текста.
Стандартные пути, параметры экрана, CPU и памяти остаются читаемыми.
Уровни WARNING/ERROR из вывода контейнера сохраняются, даже если строка пришла через stdout.
Предупреждение отдельного компонента само по себе не означает, что Android не загрузился.

Это эксплуатационный лог контейнера; Android Logcat остаётся отдельной вкладкой
сессии. Старые ошибки, произошедшие до установки этой версии, не получают
утраченный вывод задним числом.

## HTTP-прокси устройства

**Среда → Сеть → HTTP-прокси устройства**: IPv4/имя хоста и порт 1–65535.
Настройка применяется и проверяется через глобальный `http_proxy` Android.
Кнопка выключения записывает `:0` и проверяет результат. Это системный HTTP-прокси
для приложений, которые его используют; логин/пароль и SOCKS не поддерживаются.
