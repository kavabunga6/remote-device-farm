# Роли и права

[К документации](../README.md) · [Администрирование](administration.md)

Откройте **Администрирование → Роли и права**, нажмите **Новая роль**, задайте название и отметьте разрешённые действия. Сохранённую роль можно назначить в разделе **Пользователи** кнопкой со щитом. У каждого пользователя одна роль; назначение доступно и для LDAP/OIDC.

## Какие права есть

| Раздел | Что можно разрешить отдельно |
| --- | --- |
| Сессии | Просмотр своих и общих сессий; запуск и очередь; завершение своих сессий; нажатия и ввод; консоль; файлы и установка приложений; внешний ADB; настройка среды; общие ссылки; Logcat |
| Все сессии | Просмотр чужих сессий; управление и принудительная остановка чужих сессий |
| Параметры запуска | Изменение ресурсов и параметров, когда разрешено профилем; отдельно — обход разрешения профиля и privileged-контейнеры в пределах политики узла |
| Узлы | Просмотр характеристик; настройка, очистка устройств и удаление узлов; подключение агентов и управление их токенами |
| Профили | Просмотр; создание, изменение, включение и удаление |
| Образы | Просмотр каталога; сборка, отмена и прогрев; настройка сборщика и registry |
| Пользователи | Просмотр; создание и изменение данных; сброс пароля; удаление |
| Роли и права | Просмотр ролей; создание, изменение, удаление и назначение |
| Команды | Просмотр; изменение состава, ограничений и доступных профилей |
| Нагрузка | Просмотр показателей |
| Журнал | История действий, запусков и остановок, диагностика и лог приложения |
| Токены | Личные API-токены и вебхуки; отдельно — системные токены |

Права просмотра включаются вместе с действиями, которым они нужны. Отключение просмотра снимает зависимые действия. Новая роль изначально не имеет разрешений. Скрытие кнопок дублируется проверками API; прямой запрос не обходит ограничение.

Просмотр всех сессий открывает чужой экран в режиме просмотра. Для управления чужим устройством требуется отдельное право. Общие ссылки продолжают ограничивать доступ своим режимом и сроком действия.

## Встроенные роли

- **Администратор** имеет все права. Его роль нельзя изменить или удалить.
- **Пользователь** сохраняет прежние возможности работы со своими устройствами. Разрешения этой роли можно изменить; переименовать или удалить её нельзя.
- Собственные роли можно редактировать и удалять. Перед удалением назначьте их активным пользователям другие роли. История удалённых учётных записей сохраняется.

При обновлении существующие администраторы и пользователи получают соответствующие встроенные роли. Последнего действующего администратора нельзя удалить или перевести в другую роль. Системная учётная запись не считается таким администратором.

## Назначение и отзыв доступа

Смена роли или её разрешений применяется к текущему входу и личным API-токенам. Открытые соединения экрана и ADB закрываются, временные ADB-допуски отзываются, ожидающие заявки на запуск отменяются. Уже работающие устройства продолжают работу. Изменение доступа записывается в журнал действий.

Следующий вход через LDAP/OIDC обновляет данные пользователя и сохраняет вручную назначенную роль. `ADMIN_SUBJECTS` определяет начальную роль новой внешней учётной записи; синхронизации ролей с группами каталога нет. Учётная запись `LOCAL_ADMIN_USERNAME` создаётся администратором при первом запуске; последующее ручное назначение роли сохраняется после перезапуска.

## Сильные разрешения

- **Расширенные параметры запуска** разрешают обход настройки профиля и privileged-контейнеры только на узлах, где администратор разрешил такой режим.
- **Управление ролями** позволяет выдать любые права, включая роль администратора.
- **Системные токены** дают неограниченный доступ к API независимо от роли их создателя.
- **Консоль и внешний ADB** дают полный доступ к Android: ими можно изменять файлы и настройки, даже если отдельная кнопка интерфейса скрыта.
- Создание пользователя и сброс пароля без права управления ролями не позволяют получить учётную запись с более сильными разрешениями.

Разрешения на запуск не отменяют ограничения команд, доступных профилей, ресурсов узла и разрешённых параметров запуска. Только встроенная роль администратора сохраняет существующие исключения из пользовательских лимитов.

Технический каталог действий хранится в [shared/permissions.json](../../shared/permissions.json). Названия и пояснения интерфейса — в общем словаре и файлах переводов. API ролей описан в [OpenAPI](../api/openapi.yaml).

## Самостоятельная регистрация

В разделе «Пользователи» откройте «Самостоятельная регистрация». Выберите роль нового пользователя и включите создание аккаунтов. По умолчанию регистрация выключена. Ссылка «Зарегистрироваться» на странице входа отображается только при включённой регистрации.

Роль назначает сервер. Запрос регистрации принимает только логин и пароль; права, лимиты и команды нового пользователя определяются действующими настройками сервиса. Встроенную роль администратора выбрать нельзя. Пользователь получает все права выбранной роли, поэтому перед включением регистрации проверьте её разрешения.

Смена роли в настройках действует только на новые аккаунты. Права существующих пользователей меняются через назначение или редактирование их ролей. Для удаления роли, выбранной в настройках регистрации, сначала укажите другую роль.

При LDAP или SSO самостоятельная регистрация недоступна: создание аккаунтов определяется провайдером входа.
