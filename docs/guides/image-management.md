# Управление образами

Откройте **Администрирование → Образы**. Для просмотра нужно право «Просмотр образов»; очистка и удаление назначаются отдельно в ролях.

Сводка показывает размер слоёв, неиспользуемые и защищённые образы; нажатие на категорию фильтрует список. Поиск сочетается с фильтрами состояния и версии Android. Digest и адрес registry можно скопировать прямо из списка.

Выбор сохраняется при смене фильтров. Панель удаления показывает количество выбранных образов и размер их слоёв; ссылка «Вне фильтра» раскрывает скрытые выбранные строки. После обновления защищённые и исчезнувшие образы исключаются из выбора. Размеры могут включать общие слои и не равны точному объёму освобождаемого места.

## Registry

Список показывает все версии `rdf-emulator`, включая версии без тега: digest, пакет Android, дату, размер слоёв и связанные профили. Поиск работает по пакету, тегу и digest. Другие репозитории не удаляются; общий registry блокирует GC.

- **Удалить образ / выбранные** — сначала откроется предпросмотр. Связанные профили отключаются автоматически. Опция **Также удалить связанные профили** скрывает их так же, как обычное удаление профиля; история сессий сохраняется.
- Образы активных сессий, занятых слотов, очереди и скачиваний защищены. Незавершённые сборки и загрузки блокируют обслуживание.
- **Предпросмотр очистки** применяет правила хранения, сохраняя все профили (включая выключенные), актуальные сборки и используемые версии.
- **Освободить место** запускает GC без удаления дополнительных версий.

Во время обслуживания новые сессии, публикация и скачивание временно приостанавливаются. Уже работающие устройства продолжают работать. Supervisor завершает текущие HTTP-запросы, удаляет выбранные манифесты, останавливает Distribution, выполняет GC и запускает Distribution снова. `--delete-untagged` не используется: версии без тега могут быть нужны профилям или индексам.

Ссылки на закреплённый digest в `rdf-emulator` учитываются также через прежний адрес registry или зеркало: смена имени сервера не обходит защиту и не скрывает связанные профили.

Удалённый digest нельзя снова включить в профиле или использовать для новой сессии. Выберите другой образ или новую сборку. Удаление не стирает локальные копии на узлах: они очищаются отдельно.

Для внешнего registry используйте инструменты его поставщика. Управление кэшем узлов работает и с внешним registry.

## Кэш узлов

Выберите узел для просмотра локальных образов. Доступны удаление конкретных копий, предпросмотр по правилам и очистка всех подключённых узлов. Отключённые узлы не затрагиваются; их можно обработать после подключения.

Агент удаляет только образы с контрактом `remote-device-farm.contract=emulator-v1`. Любые существующие контейнеры, ссылки профилей, текущий каталог, очередь и скачивания защищают образ. Чужие теги защищают общий локальный image ID. Кэш SDK/сборки и образы других приложений не затрагиваются; Docker-wide prune и принудительное удаление не используются.

Очистка откладывается, если узел готовит сессию, скачивает, собирает или проверяет образ. Если локальную копию потребуется использовать позже, она скачается заново.

Агент сохраняет время использования в `cache-usage.json` в существующем томе состояния сборок. Для ранее скачанных образов отсчёт начинается с первого обнаружения после обновления, а не с даты создания Docker-образа.

## Политики хранения

Автоочистка по умолчанию выключена. Сервер проверяет расписание в фоне независимо от открытого интерфейса; правила и задания хранятся в PostgreSQL.

- Registry: сохранять последние N версий каждого пакета и удалять только неиспользуемые версии старше заданного срока. Неизвестные сборки без подтверждённых метаданных автоматически не удаляются.
- Кэш: срок последнего использования и целевой размер в ГБ. Ноль отключает ограничение размера. При превышении выбираются самые давно использованные доступные копии.
- Интервал проверки: от 1 до 720 часов. После включения первая проверка выполняется в ближайшем цикле сервера.

Размеры включают общие слои: сумма размеров образов не равна физическому месту, которое освободит GC. Целевой размер кэша — ориентир; защищённые образы могут превышать его. Если удалять нечего, используемые образы сохраняются.

## Ошибки и история

Вкладка **История очистки** показывает ручные и автоматические задания, этап, результат и ошибки. Изменившийся предпросмотр нужно подтвердить заново. Несколько узлов получают отдельные задания; ошибка одного не скрывает результаты остальных.

После перезапуска сервер продолжает опрашивать сохранённое задание registry. Supervisor помечает незавершённое задание как прерванное. Команды удаления кэша с неизвестным результатом не повторяются автоматически: сначала обновите инвентарь.

При частичной ошибке профили могут остаться выключенными. Версии, которые фактически удалились, остаются заблокированными. Подтверждённо сохранившиеся версии можно снова выбрать в настройках профиля.

Повреждение истории использования кэша запрещает его очистку, но не останавливает агент или сессии. Исправьте `cache-usage.json` и перезапустите agent-control; потерянные даты использования отсчитываются заново. Этапы и ошибки заданий доступны также в эксплуатационном логе приложения, события завершения — в журнале действий.

## Обновление установки

Обновите сервер, web, оба контейнера агента и сервис registry:

```bash
docker compose up -d --build server web registry
docker compose -f compose.agent.yaml up -d --build agent-control agent
```

Применяйте также ваши обычные override-файлы и env-file. Не перезапускайте сборщик во время нужной сборки; завершите или отмените её сначала.

`registry_data` сохраняется без переноса данных. Новый `registry_control` хранит служебный токен и состояние supervisor; сервер получает его только для чтения. Управляющий порт 5001 не публикуется на хосте. Backend Distribution доступен только на loopback внутри контейнера. Серверу не нужен Docker-сокет.

Перед первой очисткой включите `registry_data` в резервное копирование и сохраните PostgreSQL. [Развёртывание registry](../deployment/registry.md) · [OpenAPI](../api/openapi.yaml).
