# Если что-то не работает

[← Оглавление](README.md)

Сначала определите, где возникает ошибка: веб-интерфейс, сервер, соединение агента или само устройство. Это быстрее, чем перезапускать всю ферму.

## Проверить сервер

Из каталога установки сервера:

```sh
docker compose ps
docker compose logs --tail=100 server web postgres
```

Проверка API и подключения к PostgreSQL:

```sh
docker compose exec -T server node -e 'fetch("http://127.0.0.1:8080/health").then(async r => { console.log(r.status, await r.text()); process.exitCode = r.ok ? 0 : 1; }).catch(e => { console.error(e.message); process.exitCode = 1; })'
```

Успешный результат — `200 {"ok":true}`. В базовом nginx путь `/health` наружу не проксируется: открытие `/health` в браузере не заменяет эту проверку.

## Проверить агент

На машине агента, из каталога репозитория:

```sh
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml ps
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml logs --tail=100 agent agent-control
```

Для установки из скачанного архива используйте имя Compose-файла из [инструкции агента](deployment/agent.md).

## Частые ситуации

| Что видно | Что проверить |
| --- | --- |
| Веб открывается, войти не получается | Первый логин и пароль задаются в `.env`. После смены пароля в профиле действует новый пароль, а не старое значение в файле. Для LDAP/OIDC посмотрите журнал `server`. |
| Узел не появился или «Не в сети» | Агент должен достигать `AGENT_BROKER_URL`, включая `/agent/connect`. Сверьте `AGENT_ID` и выданный именно ему токен. Прокси должен пропускать WebSocket. |
| Узел виден, но в списке выданных токенов агентов пусто | Первый агент использует bootstrap-токен из `.env` и после подключения должен отображаться с отметкой «Из конфигурации». Обновите страницу и проверьте журнал сервера; выдавать ему второй токен для появления в списке не требуется. |
| Узел отключён | Это административный запрет новых сессий. Включите узел в его настройках; уже запущенные устройства от этого не перезапускаются. |
| Есть свободные слоты, запуск недоступен | Сверьте лимиты CPU/RAM слота с профилем, доступность KVM, тип образа и требования GPU. Количество свободных мест само по себе не означает совместимость. |
| Импорт JSON: «Ошибка» у профиля | Строка ошибки содержит путь до поля (`$.profiles[0].container.env.PATH`). Неизвестные поля, зарезервированные имена переменных, опции Docker вне белого списка и `-partition-size`/`-sdcard` в аргументах отклоняются. Профили не создаются, пока в манифесте есть хотя бы одна ошибка |
| Профиль из манифеста не виден пользователям | Новые профили создаются выключенными. Включите профиль в «Профилях устройств» после проверки образа |
| Режим GPU недоступен | Для профиля с поддержкой `cuda` нужен NVIDIA container toolkit на узле; для профиля с поддержкой `gpu` задайте `AGENT_DRI_DEVICE=/dev/dri/renderD128` в конфигурации агента и убедитесь, что устройство существует (узел сообщает `driGpuAvailable`) |
| Образ скачался, но не загружается | Запустите его вручную (`docker run --rm --device /dev/kvm -p 5555:5555 образ`). Для образов HQarroum проверьте `launch.emulatorParamsEnv: EXTRA_FLAGS`, `farmFlags: ["partition-size"]` и `MEMORY`/`CORES` в `container.env`: повторный `-gpu`/`-memory`/`-cores` во флагах ломает запуск |
| Значения переменных пропали или «не расшифровываются» | Значения шифруются ключом `SECRETS_KEY` (или ключом из таблицы `app_secrets`). После переноса базы на другой стенд задайте тот же `SECRETS_KEY`; иначе введите значения заново |
| Образ не найден или не разрешён | Проверьте Docker-ссылку, наличие тега в registry и `AGENT_ALLOWED_IMAGE_PREFIXES` на узле. Для закрытого registry заранее загрузите образ на узел. SDK-архив или ссылка на `.zip` не заменяют Docker-образ. [Выбор образа](guides/images.md). |
| Размер памяти или SD-карты отклонён | Проверьте максимум профиля `diskMaxGb` / `sdcardMaxGb`. Если максимум не задан, он равен значению по умолчанию. Для SD без значения по умолчанию и максимума разрешено только выключенное состояние. |
| Скачивание долго идёт | Первый запуск скачивает слои Docker на узел. Проверьте доступ узла к registry выбранного образа, место на диске и журнал `agent-control`. При повторном запуске сохранённые слои используются снова. |
| Образ скачался, Android не запускается | Проверьте `/dev/kvm`, архитектуру образа, лимиты памяти и журнал агента. У виртуальной машины может быть недоступна вложенная виртуализация. |
| Устройство завершилось с кодом 137 | Процесс был принудительно завершён; возможна нехватка памяти. Проверьте `OOMKilled` контейнера и журнал агента, прежде чем увеличивать лимиты профиля и слота. |
| Экран есть, звука нет | Включите звук кнопкой в сессии и разрешите воспроизведение в браузере. Поддержка аудио зависит от Android и образа; причина отображается рядом с состоянием потока. |
| Видео не показывается по `http://IP:8088` | Для WebCodecs нужен HTTPS или localhost. Откройте ферму по HTTPS либо используйте [локальный UI с прокси](development.md). PNG-режим включается при проблеме scrcpy на устройстве, а не при отсутствии WebCodecs в браузере. |
| ADB из браузера работает, `adb connect` — нет | Это разные пути доступа. Для локального ADB нужен опубликованный диапазон портов сервера, доступ к нему по сети и совпадение ключа с выбранным в сессии. См. [настройку сервера](deployment/server.md). |
| После правки `.env` ничего не изменилось | `restart` не перечитывает окружение контейнера. Выполните соответствующую команду `docker compose ... up -d`, сохранив параметры и Compose-файлы своей установки. |
| Освобождение сессии зависло | Если агент недоступен, сервер не может подтвердить удаление устройства. Восстановите соединение и посмотрите журнал агента. Не считайте слот свободным, пока очистка не подтверждена. |

## Сведения для разбора ошибки

Сохраните:

- время ошибки и действие, после которого она появилась;
- ID узла, ID сессии и имя профиля;
- ссылку на Docker-образ, выбранные CPU/RAM и режим графики;
- несколько строк журнала до ошибки и саму ошибку;
- версию кода: `git rev-parse --short HEAD`.

Перед отправкой уберите токены, пароли, приватные ключи и ссылки с секретными параметрами. Для обычной диагностики не нужен полный дамп базы.

## Диск и Docker-кеш

На узле:

```sh
df -h
docker system df
```

Готовые образы остаются в кеше после завершения сессий — это ускоряет следующие запуски. Данные конкретной Docker-сессии удаляются при освобождении. Очистка всех Docker-томов затронет и данные других сервисов; не используйте её как способ починить одну сессию.
