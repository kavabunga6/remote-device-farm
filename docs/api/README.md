# API: запустить устройство и выполнить проверку

[← Оглавление](../README.md)

API подходит для CI и скриптов. Создайте **личный API-токен** в разделе «API-токены». Он действует от имени вашего пользователя. Системный токен имеет права администратора и для обычного тестового запуска не нужен.

Ниже команды для Bash с `curl` и `jq`. Выполняйте их в одном терминале.

## 1. Задать адрес и токен

```sh
export RDF_URL='https://farm.example.com'
read -rsp 'API-токен: ' RDF_TOKEN
printf '\n'
export RDF_TOKEN
```

Так токен не попадает в текст команды в истории терминала. В CI передавайте его через секретную переменную задания.

## 2. Посмотреть узлы и профили

```sh
curl -fsS -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/hosts" | jq '.hosts[] | {id, name, status, slots, usedSlots}'

curl -fsS -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/profiles" | jq '.profiles[] | {id, name, image}'
```

Выберите включённый узел со свободным слотом и профиль с готовым [Docker-образом](../guides/images.md). В примере ниже `agent-1` и `android-30` нужно заменить ID из ответов вашей фермы, если они отличаются.

## 3. Создать сессию

```sh
export RDF_HOST='agent-1'
export RDF_PROFILE='android-30'

SESSION_ID=$(curl -fsS \
  -H "Authorization: Bearer $RDF_TOKEN" \
  -H 'Content-Type: application/json' \
  --data "$(jq -n --arg host "$RDF_HOST" --arg profile "$RDF_PROFILE" \
    '{hostId: $host, profileId: $profile, label: "Проверка API"}')" \
  "$RDF_URL/api/sessions" | jq -er '.session.id')
export SESSION_ID
printf 'Сессия: %s\n' "$SESSION_ID"
```

Сервер отвечает `202 Accepted`: запуск начался, но Android ещё может загружаться. Проверяйте состояние:

```sh
curl -fsS -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/sessions/$SESSION_ID" | jq '.session'
```

Команды устройству отправляйте после появления `state: "running"`. Если запуск не удался, после очистки сессия исчезнет из активного списка; подробности останутся в истории и журналах.

## 4. Выполнить команду Android

```sh
curl -fsS \
  -H "Authorization: Bearer $RDF_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"argv":["shell","getprop","ro.build.version.release"]}' \
  "$RDF_URL/api/sessions/$SESSION_ID/adb" | jq
```

Ответ содержит `stdout`, `stderr` и `exitCode`. API принимает массив аргументов; слово `adb` в него не включается. Команды ограничены правилами агента и выполняются для выбранного устройства.

## 5. Установить APK и получить журнал

```sh
curl -fsS -H "Authorization: Bearer $RDF_TOKEN" \
  -F 'file=@app-debug.apk' \
  "$RDF_URL/api/sessions/$SESSION_ID/files" | jq

curl -fsS -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/sessions/$SESSION_ID/logcat?lines=200" | jq
```

`/files` принимает один файл до 50 МиБ. Для постоянной библиотеки APK и более крупных пакетов предусмотрены отдельные маршруты `/api/apps` и `/api/sessions/:id/apps/install`.

## 6. Освободить устройство

```sh
curl -fsS -X DELETE -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/sessions/$SESSION_ID" | jq
```

Ответ `202` с `{ "ok": true, "accepted": true, "released": false }` подтверждает принятие запроса: остановка и очистка выполняются в фоне. До их подтверждения сессия имеет состояние `stopping`, а слот остаётся занят. После очистки запрос сессии вернёт `404`. Сохраните нужные скриншоты, записи и журналы до освобождения.

## Готовый помощник для CI

[scripts/rdf.sh](../../scripts/rdf.sh) работает в Bash и требует `curl` и `jq`. Для подключения ADB дополнительно нужны `adb` и GNU `timeout` (на macOS — `gtimeout` из coreutils). Скрипт использует очередь сервера: узел подбирается по профилю, архитектуре, ресурсам и доступности.

```sh
export RDF_PROFILE='android-30'
export RDF_STATE_FILE="$PWD/.rdf-session-$CI_JOB_ID"
# Необязательно: ограничить выбор одним узлом.
# export RDF_HOST='agent-1'
# ID публичного ключа, сохранённого в вашем аккаунте:
export RDF_ADB_KEY_ID='33333333-3333-4333-8333-333333333333'

bash scripts/rdf.sh create
bash scripts/rdf.sh wait 900
address="$(bash scripts/rdf.sh connect 60)"
adb -s "$address" shell getprop ro.build.version.release
bash scripts/rdf.sh logs 200
bash scripts/rdf.sh release 180
```

Вместо `RDF_PROFILE` можно описать нужное устройство: `RDF_ANDROID=14`, `RDF_API=34`, `RDF_DEVICE_TYPE=tv`, `RDF_FORM=tablet`, `RDF_FLAVOR=aosp|google_apis|google_play`, `RDF_ABI=x86_64`. Тогда сервер подберёт профиль сам (см. [заказ по параметрам](#заказ-устройства-по-параметрам)). Одновременно с `RDF_PROFILE` эти переменные не задаются.

`CI_JOB_ID` здесь — уникальный номер вашего задания; при ручном запуске задайте собственное имя файла. `create` печатает `queue:<id>`, а `wait` сохраняет назначенную сессию в этом же файле. Не разбирайте файл по первой строке: теперь это JSON. Старые файлы с одним UUID сессии всё ещё читаются.

`RDF_ADB_KEY_ID` выбирает ключ именно для этой сессии. Если его не указать, очередь запомнит текущий ключ аккаунта по умолчанию. Закрытая часть ключа должна быть заранее доступна локальному ADB-серверу. CLI не перезапускает общий ADB-сервер. Подробнее о ключах — [в руководстве пользователя](../guides/sessions.md).

### Одна команда с автоматическим освобождением

```sh
bash scripts/rdf.sh run -- bash -c '
  adb -s "$ANDROID_SERIAL" install -r app-debug.apk
  ./gradlew connectedDebugAndroidTest --no-daemon
'
```

`run` создаёт запрос, ждёт устройство, подключает ADB и передаёт дочерней команде `ANDROID_SERIAL`, `RDF_SESSION` и `RDF_STATE_FILE`. Затем освобождает сессию. Если файл состояния не задан, создаётся уникальный временный файл; его путь печатается перед запуском. Явный файл удобнее сохранять между шагами CI.

Для этой команды аренда действует 120 секунд и продлевается каждые 30 секунд. Если продление не удалось, CLI останавливает тестовую команду и начинает освобождение. После потери процесса продление прекращается; сервер остановит устройство после истечения аренды. Если агент недоступен, слот останется занят до подтверждённой очистки.

Код завершения тестов сохраняется. Если тесты успешны, а освобождение не подтверждено, команда завершится с ошибкой. Журналы и артефакты соберите внутри выполняемой команды, до её завершения: `bash scripts/rdf.sh logs 2000 > logcat.txt` можно вызывать и внутри `run`.

| Переменная | Значение по умолчанию | Для чего |
| --- | --- | --- |
| `RDF_PROFILE` | `android-30` | ID профиля |
| `RDF_HOST` | Не задан | Ограничить запуск конкретным узлом |
| `RDF_ADB_KEY_ID` | Ключ аккаунта по умолчанию | Выбрать свой ADB-ключ |
| `RDF_GPU_MODE` | Настройка профиля | `software` или `nvidia`: запрос ускорения использует CUDA/NVIDIA или DRI по возможностям выбранного узла; отдельный GPU-вариант профиля не нужен |
| `RDF_DISK_GB` | Настройка профиля | Внутренняя память Android: от 2 ГиБ до максимума профиля, не более 128 ГиБ |
| `RDF_SD_CARD_MB` | Настройка профиля | SD-карта: 0 — выключена, от 128 до 32768 МиБ в пределах максимума профиля |
| `RDF_EMULATOR_PARAMS` | Дополнительные аргументы профиля | Разрешённые аргументы Android Emulator; пустая строка очищает аргументы профиля |
| `RDF_PRIVILEGED` | `0` | `1` запрашивает расширенные права контейнера; только администратор и разрешивший это узел |
| `RDF_STATE_FILE` | `.rdf-session`; у `run` уникальный временный файл | Восстановление запроса и сессии |
| `RDF_START_TIMEOUT_SECONDS` | `900` | Ожидание очереди и запуска в `run` |
| `RDF_CONNECT_TIMEOUT_SECONDS` | `60` | Подключение и авторизация ADB в `run` |
| `RDF_RELEASE_TIMEOUT_SECONDS` | `180` | Ожидание очистки в `run` |
| `RDF_POLL_SECONDS` | `2` | Интервал проверки очереди, ADB и освобождения, в пределах таймаута операции |
| `RDF_HTTP_TIMEOUT_SECONDS` | `60` | Верхняя граница одного HTTP-запроса; сокращается до оставшегося времени операции |
| `RDF_LEASE_TTL_SECONDS` | `120` у `run`; отсутствует у `create` | Срок аренды без продления: 30–3600 секунд |
| `RDF_KEEPALIVE_SECONDS` | `30` | Период продления в `run`, меньше срока аренды |

Таймауты и интервалы задаются целыми числами секунд от 1 до 86400, без ведущих нулей; для срока аренды действуют отдельные ограничения из таблицы. Некорректные настройки `run` отклоняет до создания заявки. Пауза между опросами не продлевает заданный срок ожидания.

### Память устройства, SD-карта и аргументы запуска

Эти настройки работают одинаково в веб-интерфейсе и во всех интеграциях, использующих `rdf.sh`: Maestro, Appium, Jenkins, TeamCity, GitHub Actions и GitLab CI. Они применяются к одной новой сессии, не изменяя сам профиль.

```bash
export RDF_DISK_GB=16
export RDF_SD_CARD_MB=1024
export RDF_EMULATOR_PARAMS='-no-snapshot -no-boot-anim -change-language ru -change-country RU'
bash scripts/rdf.sh run -- bash ci/android-tests.sh
```

`RDF_DISK_GB` задаёт размер внутреннего раздела Android для приложений и данных в **ГиБ**. Это аргумент `-partition-size` эмулятора, а не лимит диска контейнера Docker или резервирование места на узле. SD-карта задаётся отдельно, в **МиБ**: `1024` — 1 ГиБ. Свободного места внутри Android будет меньше размера раздела из-за файловой системы и данных системы.

Максимум внутренней памяти задаёт `diskMaxGb` профиля; если его нет — `diskGb`. Максимум SD задаёт `sdcardMaxGb`; если его нет — `sdcardGb`, а без обеих настроек карта выключена. Например, для команды выше профиль должен разрешать не меньше 16 ГиБ внутренней памяти и 1 ГиБ SD. Выход за пределы профиля возвращает `409 storage_out_of_range`.

Чтобы вернуться к значениям профиля, уберите переменные:

```bash
unset RDF_DISK_GB RDF_SD_CARD_MB RDF_EMULATOR_PARAMS
```

Для явного отключения SD-карты задайте `RDF_SD_CARD_MB=0`. Для удаления дополнительных аргументов профиля задайте `RDF_EMULATOR_PARAMS=''`: пустая строка отличается от отсутствующей переменной. CPU и оперативная память контейнера и Android по-прежнему берутся из выбранного профиля; индивидуальные переопределения этих ресурсов через CLI пока не поддерживаются.

В прямых запросах `POST /api/sessions` и `POST /api/queue` используется вложенный объект:

```json
{
  "profileId": "android-30",
  "gpuMode": "software",
  "launchOptions": {
    "diskGb": 16,
    "sdCardMb": 1024,
    "emulatorParams": "-no-snapshot -no-boot-anim -change-language ru -change-country RU"
  }
}
```

API также принимает `diskGb` и `sdcardGb` на верхнем уровне: это целые ГиБ; `sdcardGb: 0` выключает карту. Например, верхнеуровневое `sdcardGb: 1` соответствует `launchOptions.sdCardMb: 1024`. Можно передать одну форму. Если переданы обе, значения должны совпадать: противоречие возвращает `400`. Ограничения профиля действуют в обоих случаях. CLI использует вложенную форму.

Для `POST /api/sessions` также нужен `hostId`; очередь выберет узел сама. Неизвестные поля `launchOptions`, неверные размеры и запрещённые аргументы отклоняются с `400 invalid_launch_options`. Эти параметры относятся к эмуляторам и не изменяют подключённые USB-устройства. CLI проверяет размеры и длину строки до отправки запроса; сервер и агент проверяют сами аргументы.

Значения сохраняются в заявке очереди и файле восстановления. Повтор запроса с тем же файлом использует исходные параметры, даже если переменные окружения уже изменены. Для нового набора параметров завершите прежнюю сессию и создайте новую заявку.

#### Какие аргументы разрешены

Строка до 500 символов **заменяет** дополнительные аргументы профиля целиком. Аргументы разделяются пробелами, без кавычек и shell-команд. Один и тот же аргумент нельзя передавать дважды.

| Аргумент | Значения |
| --- | --- |
| `-no-snapshot`, `-no-snapshot-load`, `-no-snapshot-save` | Без значения: управляют загрузкой и сохранением снимков Android |
| `-no-boot-anim`, `-wipe-data`, `-no-window` | Без значения: анимация загрузки, очистка данных и окно эмулятора |
| `-no-audio` / `-noaudio`, `-no-cache` / `-nocache` | Без значения: отключение звука или кеша |
| `-show-kernel`, `-verbose` | Без значения: дополнительный диагностический вывод |
| `-timezone` | Часовой пояс, например `Europe/Moscow` |
| `-change-language`, `-change-country` | Код языка из 2–3 букв и код страны из 2 букв, например `ru` и `RU` |
| `-netdelay` | `none`, `gsm`, `hscsd`, `gprs`, `edge`, `umts`, `hsdpa`, `lte`, `evdo` либо задержка в миллисекундах от 0 до 60000, например `100:300` — диапазон от 100 до 300 мс |
| `-netspeed` | `full`, перечисленные сетевые режимы либо скорость в кбит/с от 1 до 1000000; `1024:2048` задаёт исходящую и входящую скорость отдельно |
| `-camera-front`, `-camera-back` | `emulated`, `none` или `environment` |
| `-screen` | `touch`, `multi-touch` или `no-touch` |

Значения аргументов описаны в [справочнике Android Emulator](https://developer.android.com/studio/run/emulator-commandline). Ферма принимает только перечисленный набор.

#### Расширенные права контейнера

Режим не реализован. `launchOptions.privileged` и `RDF_PRIVILEGED` зарезервированы; агент отклоняет привилегированный запуск. Стандартный контейнер запускается без `--privileged`.

Проброс каталогов узла, QEMU passthrough и произвольная строка `docker run` не поддерживаются. Диски задаются отдельными полями, GPU — через `gpuMode`; переменные `containerEnv` задаёт администратор в профиле.

### Если запрос или освобождение прервались

Файл состояния сохраняется **до** отправки запроса. `wait` и `release` повторяют неопределённый запрос с тем же ключом идемпотентности, поэтому вторая сессия не создаётся.

`release` не считает ответ `202` завершённой очисткой: команда ждёт исчезновения сессии. При сетевой ошибке или таймауте файл остаётся на месте. Повторите команду с тем же `RDF_URL`, аккаунтом и `RDF_STATE_FILE`:

```sh
bash scripts/rdf.sh release 180
```

Параллельным заданиям нужны разные файлы состояния и отдельные ADB-окружения. Скрипт блокирует одновременное изменение одного файла. Если процесс был убит через `SIGKILL`, каталог `<RDF_STATE_FILE>.lock` может остаться; удаляйте такую блокировку только после проверки, что её процесс уже не работает.

Примеры: [GitHub Actions](../ci/github-actions.md), [GitLab CI](../ci/gitlab-ci.md), [Maestro](../ci/maestro.md), [Appium](../ci/appium.md), [Jenkins](../ci/jenkins.md), [TeamCity](../ci/teamcity.md).

## Заказ устройства по параметрам

Автоматизации не обязательно знать ID профилей. Вместо `profileId` передайте объект `profile` с нужными свойствами. Сервер выберет включённый профиль, доступный вашему аккаунту: сначала рекомендуемый, затем с самым новым API.

| Поле | Значения |
|---|---|
| `android` | версия Android: `"14"`, `"12L"` |
| `api` | уровень API: `34` |
| `deviceType` | `mobile`, `tv`, `automotive`, `wear`, `desktop` |
| `form` | `phone` или `tablet` (только для `mobile`) |
| `flavor` | `aosp` (чистый Android), `google_apis` (сервисы Google), `google_play` (с Play Store) |
| `abi` | `x86_64`, `x86`, `arm64-v8a` |

```sh
# Android TV 14 с Google Play через очередь: узел подберёт сервер
curl -fsS -H "Authorization: Bearer $RDF_TOKEN" -H 'Content-Type: application/json' \
  --data '{"profile": {"android": "14", "deviceType": "tv", "flavor": "google_play"}, "leaseTtlSeconds": 120}' \
  "$RDF_URL/api/queue" | jq '{id, profileId, state}'

# Планшет на чистом AOSP, на конкретном узле
curl -fsS -H "Authorization: Bearer $RDF_TOKEN" -H 'Content-Type: application/json' \
  --data '{"hostId": "agent-1", "profile": {"form": "tablet", "flavor": "aosp"}}' \
  "$RDF_URL/api/sessions" | jq '.session | {id, profileId}'

# Какие профили подходят под те же условия
curl -fsS -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/profiles?deviceType=automotive&flavor=google_play" | jq '.profiles[] | {id, name}'
```

Если не указан ни `profileId`, ни `profile`, запрос отклоняется. Если подходящего профиля нет, сервер отвечает `404 no_matching_profile`. Неизвестное поле или неверное значение даёт `400 invalid_profile_selector`. Выбранный профиль виден в ответе (`profileId`); повторяйте его, если нужен тот же вариант при каждом запуске.

## Автоматический выбор узла и очередь

Для CI удобнее отправить запрос в очередь: сервер сам найдёт совместимый узел. `hostId` нужен только для привязки к конкретному узлу.

```sh
REQUEST_KEY="ci-$(openssl rand -hex 16)"
QUEUE_ID=$(curl -fsS \
  -H "Authorization: Bearer $RDF_TOKEN" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $REQUEST_KEY" \
  --data "$(jq -n --arg profile "$RDF_PROFILE" \
    '{profileId: $profile, label: "Проверка CI", leaseTtlSeconds: 120}')" \
  "$RDF_URL/api/queue" | jq -er '.id')

curl -fsS -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/queue/$QUEUE_ID" | jq
```

Сохраните `REQUEST_KEY` перед отправкой. Если ответ потерялся, повторите **тот же запрос с тем же ключом**: сервер вернёт прежнюю заявку, а не займёт второй слот. Для нового запуска создайте новый ключ. Ключ действует в пределах аккаунта, даже если запросы отправлены разными его токенами.

| `state` | Что делать |
| --- | --- |
| `waiting` | Ждать свободного подходящего узла; `position` показывает примерное место |
| `assigning` | Идёт назначение; `sessionId` уже известен, но сессия ещё может отсутствовать |
| `assigned` | Перейти к `GET /api/sessions/:sessionId` и ждать `running` |
| `cancelled` | Заявка отменена; если есть `error.code`, он объясняет причину |
| `expired` | Время ожидания истекло; новый запуск требует новой заявки |

Индивидуальный запрос очереди остаётся доступен после назначения и освобождения. После очистки устройства он возвращает `sessionState: "released"` и прежний `sessionId`. Обычный `GET /api/queue` показывает только ожидающие заявки.

Выбор `adbKeyId` также сохраняется при постановке в очередь. Передайте ID публичного ключа из своего аккаунта; если поле не указано, берётся текущий ключ по умолчанию. Значение `null` выбирает личный ключ фермы, если он создан. Удаление выбранного публичного ключа во время ожидания отменит заявку с кодом `adb_key_not_found`.

`leaseTtlSeconds: 120` включает аренду для CI: с момента назначения нужно продлевать её через `POST /api/sessions/:id/keepalive`, например каждые 30 секунд. Если runner пропадёт, сервер начнёт освобождение по истечении аренды. Время ожидания очереди в эти 120 секунд не входит. Для своего клиента используйте интервал продления заметно короче аренды и проверяйте ответы сервера.

Отменить ожидание:

```sh
curl -sS -X DELETE -H "Authorization: Bearer $RDF_TOKEN" \
  "$RDF_URL/api/queue/$QUEUE_ID" | jq
```

Ответ `200` подтверждает отмену или уже завершённое ожидание. Если назначение успело начаться, сервер вернёт `409`, `error.code: "queue_already_assigned"` и `entry.sessionId`. Продолжайте читать заявку до завершения назначения, затем освободите её сессию. **Ответ `404` от сессии во время `assigning` ещё не подтверждает очистку:** строка сессии может быть создана чуть позже.

## Если процесс CI пропал

Для автоматических запусков передавайте `leaseTtlSeconds`, например `120`, в заявку очереди или запрос создания сессии. Допустимый диапазон — от 30 до 3600 секунд. Сервер возвращает `leaseTtlSeconds` и `leaseExpiresAt` в сессии.

Продлевайте аренду от имени её владельца через `POST /api/sessions/:id/keepalive` каждые 30 секунд, в том числе во время запуска Android. CLI в режиме `run` делает это сам. Новый срок отсчитывается от успешного продления. После истечения сервер отвечает `409 session_lease_expired`: вернуть эту аренду к жизни уже нельзя.

Открытый ADB и команды устройству не продлевают такую аренду. Если процесс CI исчез, сервер начинает остановку в течение очередного прохода проверки — обычно не позднее 15 секунд после истечения срока. Слот остаётся занят, пока агент не подтвердит очистку. Если узел недоступен, очистка продолжится после его возвращения.

Если `leaseTtlSeconds` не передано, действуют обычные настройки простоя и максимальной длительности сессии. Их значение по умолчанию — без ограничения; поэтому для CI рекомендуется `run` с продлением аренды.

## Ошибки

Ошибки API имеют форму:

```json
{"error":{"code":"no_free_slots","message":"..."}}
```

| HTTP | Что проверить |
| --- | --- |
| `400` | Параметры запроса и допустимые аргументы команды |
| `401` | Наличие токена, его срок и отзыв |
| `403` | Права пользователя и ограничения действия |
| `404` | ID, доступ к объекту или уже завершившуюся сессию |
| `409` | Состояние устройства, занятость слотов или конфликт настроек; читайте `error.code` |

[OpenAPI](openapi.yaml) описывает основной набор маршрутов для CI. Реализация остальных маршрутов находится в [`server/src/routes`](../../server/src/routes).
