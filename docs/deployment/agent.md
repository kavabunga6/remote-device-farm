# Подключить Linux-агент

Агент работает на машине, где будут запускаться устройства. Он подключается к серверу, сообщает о свободных слотах и выполняет команды из веб-интерфейса.

Сначала [запустите сервер](server.md). Затем выберите способ установки:

- **Из репозитория** — удобно для первого узла и разработки.
- **Из архива в веб-интерфейсе** — удобно для дополнительных узлов; доступ к Git не нужен.

Все команды ниже выполняются в Bash на Linux-узле.

## Что нужно на узле

| Требование | Как проверить |
| --- | --- |
| Linux x86-64 | `uname -m` показывает `x86_64` |
| Доступный KVM | `test -c /dev/kvm && echo "KVM найден"` |
| Docker Engine 28 или новее | `docker version --format '{{.Server.Version}}'` |
| Docker Compose v2 | `docker compose version` |
| Доступ к Docker текущему пользователю | `docker info` выполняется без ошибки |
| Связь с сервером и registry образов | Узел может открыть адрес сервера и скачать выбранный образ |

Для виртуальной машины нужна вложенная виртуализация. Docker Desktop на Windows и macOS не входит в этот способ запуска: опубликованные образы Google требуют Linux с KVM. [Требования Google](https://github.com/google/android-emulator-container-scripts#requirements).

Память и процессоры должны покрывать лимиты выбранных профилей и работу самого узла. Начните с одного слота; после первого успешного запуска увеличьте вместимость в настройках узла.

## Узел для сборки образов

Для сборки через каталог требуется минимум 35 ГиБ свободного диска и 12 ГиБ
доступной памяти. Сборщик ограничен 4 CPU и 6 ГиБ памяти; агент контролирует
ресурсы хоста каждые 5 секунд и прерывает сборку при нехватке ресурсов.
[Ограничения, кеш и требования Docker](../../deploy/emulator/README.md#ограничения-сборщика).
Обычный запуск уже готового образа не требует этих резервов для сборки.

При контейнерном запуске `AGENT_IMAGE_BUILD_DISK_PATH` по умолчанию равен `/`.
Для агента, запущенного непосредственно на хосте, задайте путь к Docker data root,
чтобы контролировать раздел, на котором хранятся образы.

## Вариант 1. Установка из репозитория

### 1. Получите ID и токен

Для **первого узла** используйте значения из конфигурации сервера:

| На сервере, в `.env` | На узле, в `.env.agent` |
| --- | --- |
| `BOOTSTRAP_AGENT_ID` | `AGENT_ID` |
| `AGENT_TOKEN` | `AGENT_TOKEN` |

Для **следующих узлов** откройте **Узлы → Подключить узел** и зарегистрируйте отдельный ID, например `agent-2`. Сохраните выданный токен: интерфейс показывает его только при создании. Токен привязан к ID узла и используется при каждом подключении агента.

### 2. Создайте конфигурацию

Если сервер уже установлен из этого репозитория на той же машине, используйте его каталог: `git clone` и `cd` повторять не нужно.

```bash
git clone https://github.com/kavabunga6/remote-device-farm.git
cd remote-device-farm
cp .env.agent.example .env.agent
chmod 600 .env.agent
```

Откройте `.env.agent` в редакторе и заполните параметры:

```dotenv
AGENT_ID=agent-1
AGENT_NAME=Лаборатория — узел 1
AGENT_TOKEN=ВСТАВЬТЕ_ВЫДАННЫЙ_СЕРВЕРОМ_ТОКЕН
AGENT_BROKER_URL=wss://farm.example.com/agent/connect
AGENT_HOST_IP=192.0.2.20
AGENT_SLOTS=1
AGENT_ALLOWED_IMAGE_PREFIXES=us-docker.pkg.dev/android-emulator-268719/images/
AGENT_EMU_CONSOLE=auto
```

GPU для контейнеров: для NVIDIA нужен работающий драйвер и NVIDIA Container Toolkit; для графики через DRI добавьте `AGENT_DRI_DEVICE=/dev/dri/renderD128`. Узел сообщает готовые способы подключения в `gpuCapabilities` (`cuda` и/или `gpu`). При включении GPU в запуске сессии ферма автоматически выбирает доступный способ и передаёт соответствующее устройство контейнеру. Настройки поддержки GPU в профиле нет (см. [образы](../guides/images.md)).

Для первого узла `AGENT_ID` должен совпасть с `BOOTSTRAP_AGENT_ID` сервера (в быстром запуске это `agent-1`); токен возьмите из серверного `.env`. Для дополнительного узла подставьте ID и токен, выданные вместе в интерфейсе.

Замените адрес сервера и IP на свои. `192.0.2.20` — пример адреса узла для отображения в интерфейсе. Если у узла нет подходящего постоянного IP, оставьте `AGENT_HOST_IP` пустым.

Для сервера, запущенного на **той же Linux-машине** через основной Compose-файл с портом `8088`, адрес подключения такой:

```dotenv
AGENT_BROKER_URL=ws://host.docker.internal:8088/agent/connect
```

Для отдельного сервера используйте доступное с узла имя или IP и порт. Например, для HTTPS на порту `8443`: `wss://192.0.2.10:8443/agent/connect`. Сертификат должен быть доверенным для Node.js внутри контейнера агента. `localhost` внутри контейнера агента указывает на сам контейнер. Для HTTPS нужен `wss://`, для HTTP — `ws://`.

### 3. Запустите агент

```bash
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml up --build -d
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml ps -a
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml logs --tail=100 agent agent-control
```

Ожидаемый результат:

- `agent` и `agent-control` работают;
- `agent-keys` завершился с кодом `0` — это разовая настройка прав;
- в разделе **Узлы** появился ваш узел со статусом **В сети**.

`--build` собирает контейнер с программой агента. Образ Android скачивается отдельно, когда пользователь запускает сессию.

Во всех последующих командах сохраняйте `--env-file .env.agent` и `-p rdf-agent`: первый параметр нужен в том числе для передачи IP, второй задаёт постоянное имя Compose-проекта.

## Вариант 2. Установка из веб-интерфейса

1. Войдите как администратор и откройте **Узлы → Подключить узел**.
2. Скачайте пакет `.tar.gz`. В этом же окне доступны его версия и SHA-256.
3. Укажите ID узла, IP и адрес сервера, доступный с Linux-узла.
4. Зарегистрируйте агент и скачайте `.env.agent`.
5. Перенесите оба файла в отдельный каталог на узле.

Выполните из этого каталога, подставив имя скачанного архива:

```bash
tar -xzf rdf-linux-agent.tar.gz
chmod 600 .env.agent
```

В скачанном `.env.agent` можно ограничить разрешённые источники образов. Например, только реестром Google:

```dotenv
AGENT_ALLOWED_IMAGE_PREFIXES=us-docker.pkg.dev/android-emulator-268719/images/
```

Для своего registry добавьте его префикс в этот список через запятую. Затем запустите:

```bash
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml up --build -d
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml logs --tail=100 agent agent-control
```

Архив содержит исходники агента и Compose-файл. Токен хранится отдельно, в `.env.agent`; для развёртывания из архива также нужен доступ к сети для сборки контейнера агента.

## Образы и сборщик

Профили создаются через **Профили устройств → Каталог образов**. Один из подключённых KVM-узлов работает сборщиком: скачивает SDK, собирает Docker-образ, проверяет Android и отправляет результат в registry. [Настройка registry и очереди](registry.md).

Создавайте образы через каталог. Готовые сторонние образы подключайте только после [проверки аутентификации ADB](../guides/images.md#готовые-сторонние-образы): поставляемый образ может отключать проверку ключей. Сборщик должен иметь свободный диск и память; рабочие сессии имеют приоритет перед проверкой сборки. Том `agent_image_builds` сохраняет задания после перезапуска. Если ограничены источники, добавьте `<адрес-registry>/rdf-emulator` в `AGENT_ALLOWED_IMAGE_PREFIXES`.

## GPU

Ускорение выбирается при запуске сессии по возможностям узла. Профиль не задаёт GPU-поддержку. Драйверы устанавливаются администратором хоста.

### Intel/AMD (DRI)

Укажите `AGENT_DRI_DEVICE=/dev/dri/renderD128` в `.env.agent`, проверьте путь и запустите:

```bash
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml -f compose.agent.dri.yaml up -d --build
```

Сохраните оба `-f` при последующих обновлениях. Render node доступен только `agent-control`; агент сообщает возможность DRI серверу.

### NVIDIA

Сначала установите совместимый драйвер и NVIDIA Container Toolkit на хосте. Проверьте GPU обычным тестовым контейнером согласно документации Toolkit; конфигурация Docker влияет на все его потребители.

```bash
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml -f compose.agent.nvidia.yaml up -d --build
```

Требуется Compose 2.30+ для `gpus`. Дополнение даёт I/O-агенту `nvidia-smi` и телеметрию. Устройства и графические библиотеки контейнеру Android подключает `agent-control`; переключатель запуска задаёт режим автоматически. Проверяйте фактический рендерер Android, а не только наличие GPU в карточке.

Дополнительные Compose-файлы берутся из репозитория. Для установки из архива перенесите соответствующее дополнение рядом с `compose.agent.yaml`.

## Очистка и обновление

При завершении эмулятора удаляются его контейнер, writable layer, анонимные тома и сети. Ошибка очистки удерживает слот и повторяется; агент уведомляет администратора. Не освобождайте слоты вручную до устранения причины.

USB включается только с явным allowlist и стратегией полной очистки. [Контракт устройства](../device-providers.md) · [Скрипт сброса](../usb-reset-script.md). Храните состояние карантина и ADB-ключи на постоянном томе; неизвестное состояние не считается чистым.

Обновляйте только сервисы агента через его Compose-проект. Не используйте глобальные `docker system prune`, `docker compose down -v` или перезапуск Docker как обычный способ обновления. `down -v` удаляет ключи, карантин и журнал сборок.

```bash
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml up -d --build
docker compose --env-file .env.agent -p rdf-agent -f compose.agent.yaml logs --tail=100 agent agent-control
```
