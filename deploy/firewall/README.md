# Сетевая изоляция эмуляторов

По умолчанию эмулятор в сессии получает «выход наружу» через обычный Docker bridge. Без фильтра из него
можно достучаться до домашней или офисной сети, до самого узла фермы и до его служб. Скрипт ниже закрывает это.

## Что делает

Агент называет bridge выходной сети каждой сессии `rdfe<11 hex>`. Скрипт `rdf-egress-firewall.sh` вешает на
все такие интерфейсы одно правило в цепочку `DOCKER-USER`:

- интернет доступен;
- частные диапазоны (`10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `100.64/10`), loopback и multicast закрыты;
- другие Docker-сети узла и `docker0` закрыты безусловно, даже при широком `ALLOW_DEST`;
- запросы к самому узлу (SSH, агент, база данных) отбрасываются в цепочке `INPUT`;
- уже установленные соединения к запрещённым адресам тоже прерываются при включении защиты.

Управляющая сеть (экран, ADB, ввод) внутренняя и правилами не затрагивается.

## Установка на узле фермы

```sh
sudo install -m 0755 rdf-egress-firewall.sh /usr/local/sbin/
sudo install -m 0644 rdf-egress-firewall.service /etc/systemd/system/
sudo tee /etc/rdf-firewall.conf >/dev/null <<'CONF'
# Частные DNS-серверы, к которым эмулятору разрешён прямой доступ.
# Укажите IP отдельного резолвера в LAN; DNS самого узла блокируется цепочкой INPUT.
ALLOW_DNS="192.0.2.53"
# внутренние тестовые стенды, которые эмуляторам разрешено видеть
ALLOW_DEST=""
CONF
sudo systemctl daemon-reload
sudo systemctl enable --now rdf-egress-firewall
sudo rdf-egress-firewall.sh status
```

Правило привязано к имени bridge, поэтому сессии, созданные до обновления агента, остаются без защиты, пока
не будут перезапущены.

## Проверка

Запустите сессию и выполните в консоли устройства:

```sh
ping -c1 8.8.8.8        # должен отвечать
ping -c1 <IP-узла>      # не должен
ping -c1 192.0.2.53    # не должен (если адрес не разрешён в ALLOW_DEST)
```

В выводе `status` растут счётчики пакетов правил DROP. Проверьте также TCP-соединение к IP узла и
соседнему адресу LAN: один только ICMP не доказывает изоляцию. Если DNS из эмулятора идёт прямо к частному
резолверу, добавьте его адрес в `ALLOW_DNS`. Встроенный DNS Docker (`127.0.0.11`) может пересылать запросы
через сам Docker daemon и не подчиняется правилу `ALLOW_DNS`; проверьте разрешение имён отдельно при
включённом и отключённом выходе в сеть.

`systemctl restart rdf-egress-firewall` обновляет правила без окна открытого доступа. Остановка unit оставляет
их активными. Для явного снятия защиты после завершения всех сессий используйте
`sudo rdf-egress-firewall.sh remove`.

## Ограничения

- Скрипт написан для `iptables`; для чистого nftables нужны эквивалентные правила в `DOCKER-USER`.
- IPv6 в сетях сессий выключен, отдельных правил для него нет.
- Скрипт не проверялся на реальном узле. Проверьте его на одном узле до раскатки на всю ферму.
